# FarmaControl — trazabilidad contable para F1

Este documento registra la clasificación revalidada para la integración de F1. El alcance se limita a integridad de asientos y fallos cerrados. No autoriza F2, F3 ni F4.

## Estado de auditorías

| Referencia                                           | Clasificación para F1                                   | Evidencia actual y trabajo pendiente                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AUD-CT-001 — Asientos omitidos                       | Corregido para operaciones nuevas con handler contable. | Los flujos que invocan `AccountingEngineService` propagan los errores y ejecutan la escritura operativa y el asiento en una transacción PostgreSQL. `JournalService.post` exige `SERIALIZABLE` cuando recibe un cliente transaccional y resuelve los mapeos requeridos sin retorno silencioso. Los movimientos sin handler quedan clasificados aparte en AUD-CT-006. |
| AUD-CT-002 — Costos históricos incorrectos           | Pendiente — F2.                                         | El costo de salida y la valoración histórica requieren el submayor y una política aprobada. Las rutas de operación revisadas que llaman al motor son ventas y anulaciones, compras recibidas, notas crédito y débito, gastos y sus pagos/reversiones, pagos de cartera y pagos a proveedores. Las pruebas de F1 deben validar las transacciones en PostgreSQL; esta lista no afirma que movimientos sin handler estén ya contabilizados.

## Diagnóstico histórico preliminar

Una consulta de solo lectura en una base local antigua produjo 13 registros candidatos sin asiento original publicado: 7 compras recibidas por **$1.080.000,00** y 6 ventas completadas por **$35.150,00**, todas con fechas entre el 27 de septiembre y el 4 de octubre de 2026. El total bruto documental candidato es **$1.115.150,00**.

Este resultado no identifica operaciones productivas sin contabilizar. La base consultada no estaba autorizada como fuente de producción, no tenía períodos fiscales ni `treasury_documents` del esquema actual y no contenía respaldo documental adjunto. Se conserva únicamente como diagnóstico preliminar para una conciliación futura con fuente actual autorizada. No se generaron asientos ni se modificaron períodos históricos.
